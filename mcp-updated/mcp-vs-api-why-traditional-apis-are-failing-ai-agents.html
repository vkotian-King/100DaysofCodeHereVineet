MCP vs API: Why traditional APIs are failing AI agents

Google Cloud Tech · Watch on YouTube · captured 2026-08-14

Summary

MCP (Model Context Protocol) is a standard that lets AI models discover and call tools automatically, instead of developers hand-writing custom integration code for every API. It doesn't replace APIs — it replaces the middleware between a model and the APIs it needs to use, the same way HTTP standardized how browsers talk to servers.

Key Insights

  • Traditional APIs assume a program (with a developer behind it) is the client. With MCP, the model itself is the client — it reads a tool's JSON-schema description and decides what to call, instead of being told exactly which endpoint to hit.
  • An MCP server sits next to an existing service (e.g. Gmail, Notion, Jira) and describes what it can do via JSON schemas — the model discovers inputs/outputs at runtime rather than needing hardcoded prompts for every action.
  • This removes the "teach the model every endpoint via a long prompt" pattern — one MCP interface can be used by any compliant model, instead of writing N custom integrations.
  • Security is still an open problem: permission layers, scopes, and auth need to live inside the protocol so a model can't take an unintended action (e.g. deleting data) — this part of the spec is still maturing.

Tools / Frameworks Mentioned

  • MCP (Model Context Protocol)
  • JSON Schema (for describing tool inputs/outputs)
  • WebSocket / HTTP (transport between model and MCP server)
  • Example integrations referenced: Gmail, Notion, Jira

Skills

  • Thinking in terms of "capabilities and context" for a model to reason over, rather than hardcoded endpoints and routes
  • Designing a tool description (schema) instead of writing prompt-level integration instructions
